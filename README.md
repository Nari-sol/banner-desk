# 社内バナー制作案件管理デスク (Banner Production Desk)

社内でのバナー制作依頼、日程調整、質問・回答、修正指示、画像提出（版管理）、納品、評価をワンストップで管理するWebアプリケーションです。

---

## 主な機能と特徴

### 1. ログインと権限管理 (3つのロール)
- **依頼者 (Requester)**: 自分が作成した案件のみ閲覧・修正依頼・日程承認・評価。
- **デザイナー (Designer)**: 自分が担当する案件の閲覧・日程提示・画像提出（初稿・修正版）・質問回答。
- **管理者 (Admin)**: 全案件の確認、担当デザイナーの割当、業務ルール（営業日・休業日・期限・採点基準・メール通知）の設定。
- ※ 画面右上のユーザーメニューからワンクリックで各ロールを即座に切り替えてテスト・実務操作が可能です。

### 2. 制作依頼登録
- 案件名、目的、主な訴求内容、必須掲載事項、掲載先、サイズ、枚数、希望最終納品日、担当デザイナー指定、添付素材（複数ファイル）を登録。
- 登録と同時に、設定された営業時間・休業日・受付カットオフ時刻に基づき「一次返信目標」および「初稿目安日」が自動算出されます。

### 3. 案件一覧ダッシュボード
- ステータス（受付待ち、内容確認中、制作中、依頼者確認待ち、修正中、納品済み、取消）で進捗管理。
- **「誰の対応待ちか」「次の期限はいつか」**が一覧上で一目で把握可能（期限超過時は赤色バッジで警告）。

### 4. 日程の合意・履歴管理
- 「初稿提出日」と「最終納品日」を独立管理。
- デザイナーが日程を提示し、依頼者が承認することで正式確定。
- 変更理由、提案者、承認者、変更前後の日程を履歴として永久保持。

### 5. 案件連絡タイムライン & 監査ログ
- コメント、質問、回答、修正依頼を時系列でタイムライン表示。投稿者と日時を自動記録。
- 投稿の編集・削除を行っても、**編集前・削除前の内容が履歴（監査ログ）として保持**され、アコーディオンで確認可能。

### 6. ワンアクション定型操作 & 版管理
- **「日程提示」「初稿提出」「修正版提出」「納品完了」**の専用アクションボタンを用意。
- 投稿・添付・提出日時の記録・状態変更を1回の操作で確実に実行。
- 提出画像は版（第1版 初稿、第2版 修正版、最終納品版）を自動インクリメントし、サムネイル表示・拡大プレビュー・ダウンロードが可能。
- 二重クリック防止および冪等性キー（Idempotency Key）により、二重送信や重複通知を完全ブロック。

### 7. 期限管理 & 業務ルール設定
- 営業日（月〜金）、休業日・祝日一覧、業務開始・終了時刻、当日受付締切時刻（カットオフ）を設定画面から自由に調整可能。
- デザイナーの発言や初稿提出をもって「一次返信完了」を自動記録。

### 8. アプリ内通知 & メール通知設計
- アプリ内通知ベル（未読バッジ）を標準装備。
- 外部メール送信機能は管理画面からSMTP情報を後から設定可能（未設定時は画面上で「未設定（未送信）」と明示され、送信済み扱いになりません）。

### 9. 評価・振り返り
- 案件ごとに「品質・デザイン完成度」「やりとり・レスポンス」「ケアレスミスの少なさ」の3軸で採点可能（採点基準マスターも管理画面で設定可能）。
- 納期遵守は品質評価と分離し、合意納期と実際の提出日時を客観対比。
- 遅延理由やミスの責任判断（依頼者側起因／制作側起因／その他）を人間が入力して蓄積可能。

## 起動方法

### 簡単起動（Windows）
フォルダ内の `start_app.bat` をダブルクリックしてください。

### コマンドラインからの起動
```bash
python app.py
```
起動後、ブラウザで [http://localhost:5000](http://localhost:5000) にアクセスしてください。

## ログインと認証仕様

ログイン画面はロール選択ボタンのみに統一されています。

### 1. 依頼者（販売促進部 / ウェルネス事業部 / 管理部）
- 各部署のボタンをクリックするだけで、**パスワードなしのワンクリックで即座にログイン**できます。
- ログイン後は自部署が依頼した案件のみが表示され、他部署の案件や管理設定画面へはアクセスできません。

### 2. 岡本（管理者 / デザイナー）
- 「岡本（管理者 / デザイナー）」ボタンをクリックすると、専用の**6桁パスコード入力画面**へ遷移します。
- 正しいパスコードを入力した場合のみ、管理者兼デザイナーとして全案件管理画面へアクセスできます。
- パスコードは環境変数 `ADMIN_PASSCODE` で管理されます。

### 4. ログアウトとセキュリティ
- **全画面共通ヘッダー右上に「ログアウト」ボタンを常時配置**: 依頼者・岡本のどちらでログインしていても、1クリックで安全にログアウトできます。
- **セッション完全解除**: ログアウト時にサーバー側セッションが完全に破棄され、ログイン画面へリダイレクトされます。
- **ブラウザ「戻る」およびURL直アクセス防止**: 全レスポンスにキャッシュ無効化ヘッダー（`Cache-Control: no-store` 等）を付与しており、ログアウト後にブラウザの「戻る」ボタンを押しても直前の画面は復元されず、強制的にログイン画面へ転送されます。
- **岡本の再認証**: ログアウト後に再度岡本としてログインする場合は、必ず再度6桁パスコードの入力が必要となります。
- **別部署への切り替え**: ログアウト後、すぐにログイン画面から別の部署を選択してログインし直すことができます。

## データの永続化

すべてのデータは `data/` 配下に保存され、アプリの再起動や再デプロイ後も完全に保持されます。
- `data/desk.db`: SQLiteデータベース（WALモード有効、同時利用耐性）
- `data/uploads/projects/{id}/briefs/`: 依頼時の添付素材
- `data/uploads/projects/{id}/versions/`: 提出された各版の画像・納品物
